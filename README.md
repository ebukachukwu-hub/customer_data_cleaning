# Customer Data Cleaning Pipeline

A PySpark-based data engineering project that cleans, validates, analyzes, and exports messy customer data.

## Project Overview

This project demonstrates an end-to-end data cleaning pipeline built with PySpark.

The pipeline takes a raw customer dataset containing common data quality issues, including inconsistent text formatting, missing values, invalid data types, unrealistic values, duplicate records, and potential outliers.

The data is processed through multiple cleaning and validation stages before being analyzed and saved in both CSV and Parquet formats.

* **`main.py`** — Controls the entire pipeline and connects all stages together.
* **`src/extract.py`** — Creates the Spark session and reads the raw customer dataset.
* **`src/transform.py`** — Contains the data cleaning, validation, duplicate removal, outlier detection, and data quality logic.

## Data Cleaning Process

The raw customer dataset contains several common data quality issues. The pipeline processes the data through the following stages.

### 1. Text Cleaning

Text values are standardized to improve consistency.

This includes:

* Removing unnecessary spaces.
* Standardizing gender values to uppercase.
* Standardizing city names.
* Cleaning inconsistent text formatting.

### 2. Missing Value Handling

Records containing important missing values are identified and handled to prevent incomplete data from affecting later stages of the pipeline.

### 3. Data Type Conversion

Columns are converted into appropriate data types.

For example:

* Age is converted to an integer.
* Income is processed as a numeric value.

Invalid values that cannot be converted correctly are identified during the cleaning process.

### 4. Data Validation

The dataset is validated using business rules.

The pipeline checks that:

* Age is between 18 and 100.
* Income is not negative.
* Invalid records are removed.

### 5. Duplicate Removal

Duplicate records are detected and removed using PySpark's `dropDuplicates()` function.

### 6. Income Outlier Detection

The project uses the Interquartile Range (IQR) method to identify potential income outliers.

The process calculates:

* First Quartile (Q1)
* Third Quartile (Q3)
* Interquartile Range (IQR)
* Lower Bound
* Upper Bound

Potential outliers are identified but are not automatically removed because unusual values may still represent valid customer data.

### 7. Data Quality Checks

The final dataset is checked for:

* Remaining null values.
* Duplicate customer IDs.
* Invalid ages.
* Negative incomes.
* Final record count.

These checks help confirm that the cleaning pipeline has produced a reliable dataset.

## Customer Reporting

After the data has been cleaned and validated, the pipeline generates a summary report containing:

* Total number of valid customers.
* Average customer age.
* Average customer income.
* Number of customers by city.
* Number of customers by gender.

This demonstrates how cleaned data can be used to generate useful insights.

## How to Run the Project

### 1. Clone the Repository

```bash
git clone <your-repository-url>
```

Navigate into the project folder:

```bash
cd customer_data_cleaning
```

### 2. Create and Activate a Virtual Environment

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

### 3. Install Dependencies

Install the required packages:

```bash
pip install -r requirements.txt
```

### 4. Run the Pipeline

Run:

```bash
python main.py
```

The pipeline will:

1. Read the raw customer dataset.
2. Clean and standardize text values.
3. Handle missing values.
4. Convert data types.
5. Validate customer records.
6. Remove duplicate records.
7. Detect potential income outliers.
8. Run data quality checks.
9. Generate a customer summary report.
10. Save the cleaned data as CSV and Parquet.

## Output

After the pipeline runs successfully, the cleaned data is saved in:

```text
data/
└── clean/
    ├── customers_clean.csv/
    └── customers_clean.parquet/
```

Spark writes the output as directories containing one or more part files. This is normal behavior when working with distributed data processing.
